# Contributing to Networking Tools
Thank you for your interest in contributing the the Networking tools Project! Contributions are always welcome and can include many different features,
however in order to keep things organized, there is a specific way that you can contribute to help the project. 

# How to Contribute
1. Any contribution begins with an issue, whether that is one being created by the contributor or an already existing issue, that's where it all starts
2. Fork the Repository and clone locally to have a copy of everything on your own system. Then create a branch of any changes that you make
3. Make your changes and test them to make sure it works as expected, does not break any other part of the code, and handles special conditions
4. Commit your changes to your branch and push your branch to origin so that I could evaluate and check your changes
5. Finally open a pull request against the project's main branch with a description of the changes, the issue number being addressed, and any additional information that can be useful

# Code Style and Formatting
Code will mainly be in C and Python and all code should be written to be readable, consistent, and easy for other and all contributers to understand.

# C Style
- use 4 spaces for indentations
- use snake_case for all variables and functions
- use descriptive names for variables unless it's for a simple loop
- use comments to explain your thought process within your code
- close sockets, files, and other resources when not needed. Also remember to free memory if allocated
  
# Python Style
- use 4 spaces for indentations
- use snake_case for all variables and functions
- use blank lines to seperate sections within code
- use a space around all operators
- use descriptive names for variables unless it's for a simple loop
- Avoid unnecessary global variables
- use comments to explain your thought process within your code

# Testing 
Make sure to run any test in a safe testing environment such as a Virtual Machine in order to protect your local system.

# Bugs and new features
If there are any bugs that you find or any features you want added, report them in the Issues section on Github with a description of the bug/feature. 
This helps a ton and allows for a smooth community workflow

# Community Guidelines
I expect respectful communication within this Project no matter the type of question. Anyone who is disrespectful to others will be banned from contributing to this project
